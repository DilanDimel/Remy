App sign-in fixes (Dilan, Nov 25 ~9:46 UTC; thread cmsg_012oEYinQ9jHxQSr4gSXfn6cQHwJ77iLYwP1uYjTaESQmu). Touches `native/` (read `docs/ai/status/demetre.md` first, as the app fix-up does).

- Google and LinkedIn sign-in in the app (the website's two Supabase providers; Apple is off on the site too). `native/src/app/sign-in.tsx` opens `<supabase>/auth/v1/authorize?provider=…&redirect_to=<Linking.createURL("auth")>` with `WebBrowser.openAuthSessionAsync` and PKCE (`newVerifier`, plain method; the return link carries only a one-time `?code`, which the app swaps at `/auth/v1/token?grant_type=pkce` with the verifier it kept, so another app catching `remy://` gets nothing usable), reads it with `parseReturn` (`native/src/lib/auth.ts`, tested) and posts the token to the existing `POST /api/auth/supabase`. Buttons only show for providers switched on in `/api/config`. `native/src/app/auth.tsx` catches the `remy://auth` link so the router doesn't show "not found".
- Supabase Auth → URL Configuration → Redirect URLs must list `remy://auth` exactly (the app; add the exact Expo Go URL only if testing there), or Supabase sends people to the Site URL instead of back to the app.
- Layout: the email and code steps sit in the middle of the screen (max 440 wide), Back stays at the top, Send code / Sign in sit under the field instead of at the bottom.
- Privacy and Terms links (welcome, email step, terms gate) open inside the app in the `/web` sheet (`/privacy`, `/terms`, `/policies`), not the outside browser.
- The "no code email" report: both codes Dilan asked for (09:44 UTC) were sent by Resend and delivered to his Gmail; nothing was broken on the server.

Supabase logs showed the callback succeed and redirect to `remy://auth?code`, but no `/token` exchange ever came: Chrome Custom Tabs wouldn't open the app from a redirect at the end of the flow (worse after Google's phone prompt). Now Supabase returns to `https://remyai.org/api/auth/app-return` (`appReturnPage` in `server/platform/auth.ts`, test `appReturn.test.ts`), which tries the app link itself and shows a Continue button. On Android the link is `intent://auth?code…#Intent;scheme=remy;package=org.remyai.app;end` (Dilan tapped a plain `remy://` button and Chrome did nothing, #459). Only `code`/`error` pass through. Covered by the existing `https://remyai.org/**` redirect entry.
